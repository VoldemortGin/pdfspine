# Resolved script placement

`RunStyle.script_placement` optionally carries a `ResolvedScriptPlacement`.
Its constructor accepts a finite glyph scale in `(0, 1]` and a finite baseline
shift in points, **positive upward**. The caller supplies resolved geometry;
the engine does not choose OOXML superscript/subscript defaults or parse markup.

```rust
use pdf_typeset::{ResolvedScriptPlacement, RunStyle};
let mut run = RunStyle::new("Liberation Serif", 24.0);
run.script_placement = Some(ResolvedScriptPlacement::new(13.9 / 24.0, 9.0)?);
# Ok::<(), pdf_typeset::ScriptPlacementError>(())
```

The example uses geometry measured for one local LibreOffice sample. Those
numbers are not universal script constants. Consumers and their dependency pins
are unchanged by this engine increment.

## Nominal size and glyph geometry

The run's `size` remains the nominal line strut. Glyph size and advances use
`size * glyph_scale`; the painted top-down baseline is the shared line baseline
minus `baseline_shift`. A line of only script text retains nominal line metrics.
When raised/lowered effective metrics exceed that nominal envelope, the shared
line helper adds the excess to natural height. `FontIndependent` retains its
existing 1.0/0.2/1.2-em policy; `FontMetrics` retains its face metrics and original
line-gap placement. There is no global lineGap adjustment.

Multiple/AtLeast line spacing uses the expanded natural height. Exact keeps its
requested advance and nominal baseline reference; script ink can protrude, so
normal text is not inadvertently shifted by the script descent. Line measurement
reports extended ascent/descent but its `height` still obeys Exact. Empty lines
keep the existing first usable run's nominal strut, without phantom script ink.
One observed LibreOffice scripted-paragraph-mark AtLeast special case is not
reproduced: this remains a resolved engine capability, not complete OOXML parity.

Highlights, underline/strike and hyperlink bounds follow effective font metrics
at the same shifted baseline as their glyphs. Text and fragment merging include
the shift. List markers retain their existing nominal family/size/color
inheritance and do not inherit the body script placement. Normal wrapping, explicit breaks, tab stops and existing tracked
base-plus-combining handling remain in use; this does not add full shaping or
change explicitly styled combining marks into an automatic script policy.

Character spacing remains separately specified in points and is **not** scaled
merely because the run is a script. Whole-textbox font autoshrink scales nominal
size, spacing and baseline shift once, keeping the script ratio unchanged.
Table cells, textbox anchors and paragraph-border lookahead use the shared
measurement path. Existing container clips still clip protruding Exact ink.

## Defaults and invalid values

None and identity `(1, 0)` retain the previous arithmetic/emission path. Invalid
constructor values return a typed error. For a nonidentity placement only,
underflowed/overflowed effective size, nonfinite metric-envelope headroom or
nonfinite accumulated advance bounds make the affected run unusable: its text
is omitted, following the existing unusable-font-size convention. It does not
silently clamp coordinates, abort unrelated valid runs or broaden legacy style
cleanup. Empty-line reference selection skips those unusable scripted runs.

## Validation

Fifteen dedicated Rust tests cover real mixed-script red/green, identity PDF
bytes, both line-height rules, all-script/empty/mixed nominal sizes, Exact versus
AtLeast, invalid derived dimensions, tracked combining boundaries, tabs,
decorations/links, one-time box scaling, bottom-aligned box/cell agreement and
border page closure. The initial real failure merged A/2/B as ordinary text;
the implementation emits the smaller, shifted 2 and correct following advance.
Review also reproduced and fixed a None-path EPS-merge drift and invalid Exact
values using a script baseline instead of their existing natural fallback.

Seven previous generated PDFs remain byte-identical. New self-authored DOCX and
PPTX fixtures compare against LibreOffice 26.8.0.3 at 100dpi with the same
renderer: **0.9498 → 0.9637** and **0.8766 → 0.9849** respectively. The missing-
feature PDFs were generated by the actual prior `d05f9df` engine with identical
text/nominal styles and no unavailable placement field. These are local advisory
scores, not CI thresholds or universal format fidelity. Existing DOCX/PPTX,
shading, tracking and border comparisons remain **0.9822 / 0.9780 / 0.9868 /
0.9749 / 0.9836**. Readback is 7/7 order/F1/lev 1.0; renderer reference checks
are 10/10 pages at the unchanged 0.97 threshold (minimum 0.9997). Only the two new
fixture references were generated; both fixture provenance/license entries are
in `fixtures/MANIFEST.toml`.

`cargo run -p pdf-typeset --example make_typeset_fixtures` regenerates the engine
inputs. `conformance/gt/typeset_lo_oracle.py` authors the corresponding OOXML;
LibreOffice remains local-only. Committed `.ssimref` buffers are renderer
regression snapshots, not independent layout oracles. No consumers, general PDF
APIs, negative tracking, arbitrary transforms or automatic script policies are
added by this increment.
